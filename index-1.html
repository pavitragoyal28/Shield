How it works

Attackers hide commands in emails using invisible text. You never see them, but an AI assistant reading the raw message does.

shield.scan

> reading message...

> hidden blocks found: 2

> instructions removed

✓ clean text sent

Step 1

Scan

Shield reads the email the way an assistant would and finds text you can’t see, plus visible text that gives orders to the AI.

Step 2

Remove

Flagged content is stripped before the assistant gets the message, and each removal is explained in plain language.

Step 3

Summarize

The assistant works only from the clean text, so the summary reflects the real message.

What it catches

Each email gets a suspicion score from 0 to 100 based on these signals.

Hidden text
White-on-white, zero-size, off-screen, collapsed, or display:none content, and HTML comments.
Invisible characters
Zero-width and Unicode tag characters that spell out commands you can’t see.
Instruction override
Phrases such as “ignore all previous instructions” that try to cancel the assistant’s real rules.
Messages aimed at the AI
Text that speaks to the assistant instead of to the human reader.
Data exfiltration
Requests to forward messages, contacts, or password resets to an outside address.
Private data requests
Attempts to make the assistant print its system prompt, internal configuration, private instructions, keys or passwords.
Secrecy demands
Orders to hide an action from you.
Look-alike domains
The part after the @ imitates a name you know, with swapped letters or a trusted name placed in front.
Risky domains
Encoded names, personal webmail in business email, throwaway endings like .xyz, and words like “secure” or “payroll”.

    How to get a Client ID
    1. In Google Cloud Console, create a project and enable the Gmail API.
    2. Configure the OAuth consent screen and add your Gmail address as a test user.
    3. Create an OAuth client ID of type Web application.
    4. Add the address you open this page from (for example http://localhost:8000) under Authorized JavaScript origins.
    5. Paste the Client ID above and select Connect Gmail.

    Supported files and sources
    • deepset/prompt-injections: a CSV or JSONL file with text and label columns. Hugging Face offers Parquet, so convert it to CSV first.
    • Microsoft BIPIA: the attack files (a JSON object mapping each attack category to a list of strings) import as malicious. Its email contexts import as benign when “Rows with no label are” is set to Benign.
    • Lakera PINT: a YAML list with text, category and label fields.
    • Anything else: CSV, TSV, JSON, JSONL, or a text file with one example per line. Recognised columns include text, prompt, content, label, is_injection and category.

    Files are read in your browser and stored on this device only (up to about 2.5 MB, 20,000 rows per file, first 400 characters of each row). Check each dataset’s licence before using it. Evaluate scores every row against all the others, never against itself, but near-duplicate rows within a dataset can still raise the numbers.
